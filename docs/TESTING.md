# Sage Keys 回歸與效能報告

俯視鍵帽、懸浮焦點、混音輸出與省電切換的最新驗收，以及同環境的修復前後量測，見[互動修復實測](INTERACTION-REPAIR.md)。以下保留懸浮模式首次上線時的結果。

2026 年 11 月 21 日於 Codex 雲端完成。執行版本的應用程式提交為 [facd0e4](https://github.com/AnneCat-bit/sage-keys/commit/facd0e44317066ff3a06b253d76651f3b522a24f)。測試對象為正式 [GitHub Pages 工作室](https://annecat-bit.github.io/sage-keys/)。

## 正式站回歸結果

| 項目 | 實際檢查 |
| --- | --- |
| Pages 載入、路徑與重新整理 | HTTPS 專案子路徑直接開啟與重新整理成功。主程式、相對模組、字型、WAV 及索引由正式站提供。瀏覽器重新整理後仍有可操作的鍵盤。 |
| 英文、修飾鍵與多鍵 | 輸入 `Sage Keys`，同時按住實體 Shift、A、S，驗證 `AS`。實際鍵盤事件引起 WebGL 緩衝更新。另比對鍵帽頂點，A 與左 Shift 的變動範圍互不重疊，各自放開後精確復位。 |
| 繁中 IME 與編輯 | 用 Chromium 原生 IME 測試介面依次組字、送出「你」「好」「文」，取消另一段組字，換行接英文。內容為「你好文」換行後接 `test`，沒有重複或殘留。Ctrl+A、Backspace 及對話框 Escape 保持原生行為。 |
| 真實錄音 | 三個錄音庫均成功解碼並啟動 Web Audio 播放。分別檢查 Space、Enter、Backspace 三組偏移與時長，且解碼訊號有能量。一般取樣連按不會連續重複，快速打字最多五個音源，靜音時沒有新音源，音量控制可變更增益。 |
| 視角及降級 | 拖曳、滾輪、縮放、立體、俯視、重設及模式切換通過。390 px 寬度無水平溢出。停用 WebGL 時顯示 82 鍵的二維配列，仍可輸入並看見單鍵下沉回彈。 |
| 隱私及焦點 | 測試期間應用請求均為同來源靜態 GET。本地儲存僅有四個偏好欄位，重新整理後文字清空，偏好仍在。模擬失焦時停止繪製。 |
| 懸浮視窗建立 | 由點擊觸發真實 Document Picture-in-Picture，預設內容區量得 400 × 250。透過 Chrome 原生視窗介面移動位置並改成 300 × 190，控制列仍完整可用。 |
| 單一 3D 場景 | 比對移動前後的 HTMLCanvasElement 和 WebGL context，皆為同一物件。小窗開啟時主文件沒有畫布，小窗只有一個畫布，沒有重新載入主程式或書寫區。 |
| 懸浮操作與輸入範圍 | 分別在小窗及主頁輸入，均驅動同一模型。小窗按鍵觸發錄音，靜音與省電開關會同步主頁。在另一個獨立測試分頁輸入時，小窗保持開啟，模型繪製及音源計數均無增加。 |
| 懸浮結束與相容提示 | 測試小窗「返回」、原生關閉小窗、重新開啟及重新整理主頁。返回可保留原畫布及原文字，重新整理會清空文字並結束小窗。模擬瀏覽器沒有此 API 時出現說明，主頁仍能打字。 |

測試驗證瀏覽器的 composition 協定和聲音資料、播放及控制邏輯。macOS 的實體倉頡、速成、拼音候選窗、喇叭輸出延遲、Word 全螢幕置頂及跨 Spaces 行為仍需在 Mac 上實測。網站只對自己的工作室及懸浮文件註冊鍵盤事件。

## 效能量測方法

- Debian 13 雲端環境，Intel Xeon Platinum 8573C，CPU 配額相當於 4 核心。使用獨立 Chromium 156.0.8078.79 與 ANGLE SwiftShader 軟體繪圖。主頁視口為 1280 × 800，DPR 1，畫布 1150 × 414。小窗量測使用預設 400 × 250 內容區。
- 載入字型、模型、音色並預熱後，分段量測約 8 秒。輸入情境每秒觸發 8 次原生瀏覽器按鍵，交替 A 和 S，保持聲音開啟。全尺寸使用原生 textarea，小窗接收自身的物理鍵盤事件。
- CPU 為 Chrome DevTools Protocol 列舉的瀏覽器程序合計 CPU 時間增量除以經過時間。100% 代表一個核心滿載。PSS 為這些程序在 Linux 的比例分攤記憶體，已包含瀏覽器、渲染與軟體 GPU 成本。JS heap 為主工作室執行環境的樣本終點讀值，數值可隨垃圾回收波動。
- 測試程式計數 WebGL `drawElements`。本次可見模型每個渲染幀恰有五次呼叫。0 幀表示該期間應用沒有提交新 3D 畫面；瀏覽器仍維護視窗、文字游標、作業系統合成及事件處理。
- 功能測試與量測腳本均獨立於產品。自動化 Chromium 在此雲端映像使用系統受信任 CA 取得正式站的 HTTPS 回應，再交給測試瀏覽器載入。正式站回歸沒有使用專案檔案替代網絡回應。雲端互動瀏覽器也直接開啟過正式 HTTPS 網址。

## 實測數據

| 情境 | CPU（單核心 = 100%） | 瀏覽器 PSS（MiB） | 主頁 JS heap（MiB） | 新繪幀數 | 平均 fps |
| --- | ---: | ---: | ---: | ---: | ---: |
| 空白 Chromium 基線 | 1.37% | 211.3 | 1.27 | 0 | 0.00 |
| 完整頁，省電，靜置 | 0.62% | 409.6 | 8.89 | 0 | 0.00 |
| 完整頁，省電，連打及錄音 | 292.55% | 388.9 | 4.73 | 229 | 28.56 |
| 完整頁，標準，連打及錄音 | 385.34% | 393.8 | 5.18 | 433 | 53.96 |
| 完整頁，停止輸入後 | 0.50% | 392.7 | 5.18 | 0 | 0.00 |
| 小窗，省電，靜置 | 0.87% | 398.1 | 6.49 | 0 | 0.00 |
| 小窗，省電，連打及錄音 | 92.78% | 395.3 | 5.67 | 241 | 30.05 |
| 小窗，省電，停止輸入後 | 0.25% | 392.4 | 5.68 | 0 | 0.00 |

同一個省電模式下，完整頁與懸浮小窗均在 8.02 秒內接收 64 次按鍵。本次 CPU 由完整頁的 292.55% 降至小窗的 92.78%，兩者靜置期間皆為 0 次繪製。小窗引入額外瀏覽器視窗，本次打字時量得的整體 PSS 略高。對 SwiftShader 而言，持續打字仍有實質 CPU 成本。

在加入懸浮前的 [093c874](https://github.com/AnneCat-bit/sage-keys/commit/093c8740f148bdc506701d2cfe1bf93260d77d62) 亦曾量測完整頁。同樣的 1150 × 414 畫布、DPR 1、64 次按鍵及錄音，省電模式約 388.30% CPU、7.95 fps。新版保留靜態幀，只更新鍵帽附近的像素與相交幾何。這是各一次的短程雲端量測，不能推算硬體加速的 MacBook 的耗電、溫度或電池續航。

已比對正式 HTTPS 回應與測試提交中的 18 個執行資源，SHA-256 全數相符。含所有音色的未壓縮檔案總計 951,570 bytes；首頁按需載入目前選定的聲音，截圖與測試報告不在首頁載入路徑。
